# TESTING.md — проверка LinkShift на Windows

План проверки приложения (системная логика + интерфейс). Большинство сценариев выполняются в самом интерфейсе, точечные проверки — в консоли DevTools (правая кнопка мыши → **Inspect** → Console). Публичный API системного слоя доступен как `window.LM`.

## Подготовка

1. Windows 10/11, Node.js установлен.
2. В корне проекта:
   ```bash
   npm install -g @neutralinojs/neu
   neu update
   neu run
   ```
3. Откроется окно LinkShift. Внизу статусбар должен показать статус прав администратора и версию `LinkShift 0.1.0`.
4. DevTools → Console: `await LM.isAdmin()` → `true` (запуск от админа) или `false`.
5. Проверьте переключатель темы (иконка в навигации) и RU/EN — язык меняется без перезагрузки, тема запоминается между запусками.

## Т1. Канал PowerShell (кодировки)

```js
await LM.symlinkManager.checkEnvironment();
// Ожидание: { isAdmin, os: 'Windows', platform: 'win_x64', appPath: '<путь к .exe>' }

await LM.symlinkManager.getDriveSpace('D:\\');
// Ожидание: { ok: true, drive: 'D:', freeBytes: ..., totalBytes: ... }

await LM.symlinkManager.measureDirectorySize('%USERPROFILE%\\Desktop');
// Ожидание: { ok: true, exists: true, isReparsePoint: false, bytes: >=0 } — кириллица/пути без «крякозябр»
```

## Т2. Транзакция «Перенести и связать» — happy path (через интерфейс)

Создайте тестовую папку:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\Desktop\LM Test\Папка с кириллицей и пробелом"
'AAA' | Set-Content "$env:USERPROFILE\Desktop\LM Test\Папка с кириллицей и пробелом\file1.txt"
New-Item -ItemType Directory -Force "$env:USERPROFILE\Desktop\LM Test\Папка с кириллицей и пробелом\sub"
'BBB' | Set-Content "$env:USERPROFILE\Desktop\LM Test\Папка с кириллицей и пробелом\sub\file2.txt"
```

1. Вкладка «Перенос»: введите путь к папке (или «Обзор…», или перетащите папку из проводника в окно — путь должен подставиться сам).
2. Целевой каталог — на другом диске, например `D:\LinkShift`.
3. Оставьте Junction, нажмите **«Перенести и связать»**.

Проверки:
- [ ] Карточка прогресса показала шаги validate → space → rename → copy → link → verify → cleanup, бар заполнился.
- [ ] Тост «Готово! Ссылка работает…».
- [ ] В проводнике исходный путь — значок ссылки (junction), файлы открываются как раньше.
- [ ] `D:\LinkShift\Папка с кириллицей и пробелом` содержит реальные файлы; `.bak`-папки нет.
- [ ] Вкладка «История» содержит запись со статусом «Активна».

## Т3. Блокировка папки (безопасное прерывание до копирования)

1. Откройте командную строку и выполните `cd` внутрь тестовой папки (или откройте файл из нее в программе).
2. Повторите перенос из Т2.

Ожидание: тост `ERR_SOURCE_LOCKED` («папка занята запущенной программой…»), в прогрессе шаг rename — красный; на диске НЕТ ни `.bak`, ни копии; исходная папка не изменилась:

```js
await LM.symlinkManager.getLinkInfo('C:\\Users\\<user>\\Desktop\\LM Test\\Папка с кириллицей и пробелом');
// { exists: true, isReparsePoint: false } — обычная папка
```

## Т4. «Вернуть как было» (откат через интерфейс)

1. Вкладка «История» → **«Вернуть как было»** → подтвердите в нативном диалоге Windows.
2. Шаги прогресса: remove-link → move-back → cleanup-target → done.

Проверки:
- [ ] Исходный путь снова обычная папка с реальными файлами (`isReparsePoint: false`).
- [ ] `D:\LinkShift\...` удалена (после /MOVE пустая).
- [ ] **Запись удалена из истории** (список пуст).
- [ ] Повторите Т2 и Т4 еще раз — транзакция обратима в обе стороны.

## Т5. Защитные проверки валидации

| Действие в интерфейсе / консоли | Ожидаемая ошибка |
| --- | --- |
| `LM.moveAndLink({ sourcePath: 'C:\\Нет такой', targetParent: 'D:\\x' })` | `ERR_SOURCE_NOT_FOUND` |
| `LM.moveAndLink({ sourcePath: 'C:\\Windows', targetParent: 'D:\\x' })` | `ERR_SYSTEM_PATH_FORBIDDEN` |
| `LM.moveAndLink({ sourcePath: 'C:\\', targetParent: 'D:\\x' })` | `ERR_SOURCE_IS_ROOT` |
| Повторный перенос уже созданной ссылки | `ERR_SOURCE_IS_LINK` |
| Целевой каталог внутри исходной папки | `ERR_TARGET_INSIDE_SOURCE` |
| Папка с тем же именем уже есть в целевом каталоге | `ERR_TARGET_EXISTS` |
| Целевой диск почти пуст (создать маленький VHD) | `ERR_NO_FREE_SPACE` с числами need/free |

## Т6. Сканер «Пожиратели места»

1. Вкладка «Сканер диска C», порог 100 МБ → **«Найти тяжелые папки»**.

Проверки:
- [ ] Во время скана отображается текущий путь, по завершении — время и количество.
- [ ] В таблице есть категории: кэш браузера (при установленном Chrome/Edge/Yandex), кэш мессенджера, шейдеры GPU/игры, тяжелая папка AppData, временные файлы.
- [ ] Запустите Chrome и повторите скан: у его кэша бейдж «Не переносить», причина «Приложение запущено: chrome.exe», чекбокс заблокирован.
- [ ] Ни один путь в выдаче не является reparse point: для каждой строки `await LM.symlinkManager.getLinkInfo(i.path)` → `isReparsePoint: false`. Предварительно создайте тестовую ссылку `cmd /c mklink /J "C:\Users\<user>\AppData\Local\FakeLink" "D:\"` и убедитесь, что сканер ее **не показал**.
- [ ] Кнопка «Остановить» во время скана → тост «Операция отменена», процесс PowerShell завершается (Диспетчер задач).
- [ ] Кнопка «На вкладку переноса» (⇱) подставляет путь в первую вкладку.

## Т7. Пакетный перенос

1. В «Сканере» отметьте 2–3 безопасные папки (можно создать тестовые: `New-Item "$env:USERPROFILE\Desktop\LM Test\Тяжелый кэш 1"` и т.д.).
2. Укажите целевой каталог, нажмите **«Перенести выбранные (N)»** → подтвердите.

Проверки:
- [ ] Папки переносятся по очереди, в прогрессе видно `[i/N]`; после каждой успешной — строка исчезает из выдачи.
- [ ] Итоговый тост: «Перенесено: N из N. Ошибок: 0».
- [ ] Все связи появились во вкладке «История».

## Т8. Symlink и права администратора

1. Запуск **без** админа: в «Переносе» выберите Symlink → появится желтое предупреждение; после переноса в истории `linkType: junction` (fallback) + предупреждение в тостах.
2. Кнопка **«Перезапуск от админа»** → UAC → приложение перезапускается, статусбар показывает «Права администратора», `LM.isAdmin()` → `true`. Отмена UAC → приложение остается открытым, тост `ERR_UAC_CANCELLED`.
3. От админа тип Symlink → в истории `symlink`, `getLinkInfo` возвращает `linkType: 'SymbolicLink'`.
4. От админа robocopy использует `/COPY:DATS` — NTFS-права сохраняются (проверка: вкладка «Безопасность» файла после переноса).

## Т9. Отказоустойчивость отката (имитация сбоя копирования)

Создайте папку с файлом, который robocopy не сможет прочитать (например, файл, открытый с монопольной блокировкой), затем выполните Т2. Ожидание: тост `ERR_ROBOCOPY_FAILED`, после чего:
- [ ] Исходная папка на месте (возвращена из `.bak`),
- [ ] частичная копия на целевом диске удалена,
- [ ] записи в истории нет.

## Т10. Вкладка «Ссылки на диске» (внешние ссылки и их откат)

Подготовка — создайте ссылку вручную, без приложения:

```powershell
New-Item -ItemType Directory -Force "D:\ExtTest"
New-Item -ItemType Directory -Force "$env:USERPROFILE\Desktop\LM Test\Внешняя папка"
'CCC' | Set-Content "$env:USERPROFILE\Desktop\LM Test\Внешняя папка\file3.txt"
robocopy "$env:USERPROFILE\Desktop\LM Test\Внешняя папка" "D:\ExtTest" /E >$null
cmd /c rmdir "$env:USERPROFILE\Desktop\LM Test\Внешняя папка"
cmd /c mklink /J "$env:USERPROFILE\Desktop\LM Test\Внешняя папка" "D:\ExtTest"
```

1. Вкладка **«Ссылки на диске»** → корень `%USERPROFILE%` → **«Найти ссылки»**.
2. Проверки списка:
   - [ ] В выдаче есть `…\LM Test\Внешняя папка` с бейджем «Внешняя ссылка» и целью `D:\ExtTest`.
   - [ ] Ссылки, созданные приложением (после Т2/Т7), помечены «Создано в LinkShift».
   - [ ] Системные скрытые ссылки Windows («Application Data», «Local Settings» и т.п.) **отсутствуют** в списке.
   - [ ] Внутри `C:\Windows` скан не заглядывает: корень `C:\Windows` → 0 ссылок.
3. **«Вернуть как было»** у внешней ссылки → подтвердите.
   - [ ] Шаги: remove-link → move-back → cleanup-target → done.
   - [ ] `…\Внешняя папка` снова обычная папка с реальными файлами (`getLinkInfo` → `isReparsePoint: false`).
   - [ ] `D:\ExtTest` удалена (была пустой после /MOVE), записи в «Истории» для этого пути нет.
4. Ссылка без цели: `cmd /c mklink /J "$env:USERPROFILE\Desktop\LM Test\Битая ссылка" "D:\НетТакойПапки"`, повторите скан.
   - [ ] «Вернуть как было» → второй диалог «Удалить только ссылку?» → после подтверждения ссылка исчезла, тост `ERR_LINK_TARGET_MISSING` **не** появляется.
5. Повтор Т6: сканер «пожирателей» по-прежнему не показывает ни одну из созданных ссылок.
